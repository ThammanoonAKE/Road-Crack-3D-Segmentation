# Crack Detector 1 คลาส: DeepCrack + ConvNeXt-Small (รุ่น 2026-11-20)

ตรวจจับรอยแตกในภาพทีละ pixel (segmentation) โมเดลมีคลาสเดียวคือรอยแตก
รุ่นนี้เทรนเพิ่มด้วยภาพสแกนถนน line-scan ของเราเอง จึงเหมาะกับภาพสแกนของเรามากที่สุด
และเรียนรู้ด้วยว่ารอยต่อกับรอยปะไม่ใช่รอยแตก โมเดลเทรนด้วย augmentation หนัก จึงทนต่อภาพเบลอ, noise, JPEG คุณภาพต่ำ, แสงไม่ดี และเงา

## ไฟล์

| ไฟล์ | คืออะไร |
|---|---|
| `crack_detector.py` | โค้ดทั้งหมดอยู่ในไฟล์เดียว: โมเดล, ตัวช่วยใช้งาน (`CrackDetector`) และ command line |
| `deepcrack_1class_2026-11-20.pt` | weight ของโมเดล (208 MB) ต้องอยู่โฟลเดอร์เดียวกับ `crack_detector.py` หรือระบุ path เอง |
| `requirements.txt` | library ที่ต้องใช้ ได้แก่ torch, torchvision, opencv-python และ numpy |
| `plots/` | กราฟการเทรนและผลทดสอบ (ภาษาอังกฤษ) และภาพตัวอย่างผลบนภาพสแกนทดสอบของเรา |

คัดลอกทั้งโฟลเดอร์ไปไว้ในโปรเจ็คอื่นได้เลย ไม่ต้องใช้โค้ดเทรน (ซึ่งไม่ได้รวมอยู่ใน repository นี้)

ใช้แทนแพ็กเกจรุ่นก่อน (weight `deepcrack_convnext_small_aug_v3.pt`) ได้ทันที เพราะคำสั่งใช้งานเหมือนเดิม
มีสิ่งที่เปลี่ยน 3 อย่าง:
- ชื่อไฟล์ weight
- ค่าเริ่มต้น `tile=2048`
- ตัวเลือกใหม่ `min_area`

## ใช้ใน Python

```python
from crack_detector import CrackDetector

det = CrackDetector()                    # โหลด weight ข้างไฟล์, ใช้ GPU ถ้ามี (หรือ device="cpu")

mask = det.predict_mask("scan.png")      # numpy uint8 HxW: 255 = รอยแตก, 0 = ไม่ใช่
prob = det.predict("scan.png")           # numpy float32 HxW: ความน่าจะเป็น 0-1

# รับภาพได้หลายแบบ
mask = det.predict_mask(scan16)                # numpy uint16 จาก cv2.imread(path, cv2.IMREAD_UNCHANGED)
mask = det.predict_mask(frame)                 # numpy BGR จาก cv2.imread / cv2.VideoCapture
mask = det.predict_mask(rgb_array, color="rgb")  # numpy RGB
mask = det.predict_mask(pil_image)             # PIL.Image
# ภาพขาวดำ (HxW), BGRA/RGBA และ float 0-1 ก็รับได้

# ภาพ 16-bit จากกล้อง line-scan (Mono12)
det = CrackDetector()                    # PNG 16-bit ที่บันทึกไว้ (ใช้ 8 บิตบน เหมือนตอนเทรน) ใช้ค่าเริ่มต้นได้เลย
det12 = CrackDetector(input_bits=12)     # buffer ดิบจากกล้องที่มีค่า 0-4095

# หลายภาพพร้อมกัน (ภาพขนาดเท่ากันจะรันเป็น batch บน GPU ซึ่งเร็วกว่า)
probs = det.predict_batch([img1, img2, img3])
masks = [det.mask_from_prob(p) for p in probs]

# วาดผลทับภาพ (สีแดง) รับภาพ 16-bit / ขาวดำได้
vis = CrackDetector.overlay(scan16, mask)

# ร้อยละพื้นที่รอยแตก
crack_percent = (mask > 0).mean() * 100
```

### ตัวเลือกของ `CrackDetector(...)`

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `weights` | ไฟล์ .pt ข้างโค้ด | path ของ weight |
| `device` | `"cuda"` ถ้ามี, ไม่งั้น `"cpu"` | อุปกรณ์ที่ใช้รัน |
| `threshold` | `0.16` | ค่าความน่าจะเป็นขั้นต่ำที่นับเป็นรอยแตก ลดลงจะเจอรอยแตกมากขึ้น (เส้นหนาขึ้น และเจอเส้นจางได้มากขึ้น) แต่ก็ทายผิดมากขึ้นด้วย |
| `min_area` | `150` | `predict_mask` ตัดบริเวณรอยแตกที่เล็กกว่า 150 pixel ทิ้ง (ค่าที่ใช้วัดผลบนภาพสแกนของเรา) ใส่ `0` เพื่อเก็บทั้งหมด |
| `amp` | `True` | ใช้ bf16 บน GPU ซึ่งเป็นค่าที่ใช้วัดความแม่นในตาราง และเร็วกว่า |
| `input_bits` | `16` | จำนวนบิตของภาพ uint16: 16 = ใช้ 8 บิตบนของช่วง 0–65535, 12 = Mono12 ดิบ (0–4095) |
| `tile` | `2048` | ภาพสแกน 2048×2048 รันทีเดียวทั้งภาพ เหมือนตอนวัดผล (ใช้หน่วยความจำ GPU ราว 5.8 GB) ภาพที่ใหญ่กว่านี้จะถูกแบ่งเป็นชิ้นที่ซ้อนทับกัน ถ้าหน่วยความจำไม่พอให้ใส่ `1024` (ราว 2 GB, ได้รอยแตกมากกว่าเดิมราว 3% ส่วนใหญ่ที่ขอบเส้น) |

### ตัวเลือก `scale` (ขนาดของรอยแตกในภาพ)

โมเดลเทรนจากภาพ 448×448 ที่ถ่ายใกล้รอยแตก และภาพสแกนของเราที่ความละเอียดเดิม
ภาพสแกนของเราใช้ `scale=1` (ค่าเริ่มต้น)
ภาพอื่นที่ใหญ่มาก เช่นภาพมือถือ 4000×3000 ที่ถ่ายถนนทั้งเลน ให้ลองย่อภาพก่อน ผลที่ได้จะถูกขยายกลับเป็นขนาดเดิมให้อัตโนมัติ

```python
mask = det.predict_mask(big_photo, scale=0.5)    # ลองค่า 0.25-0.5 กับภาพความละเอียดสูง
```

## ใช้ผ่าน command line

```bash
python crack_detector.py scans/ --out results/ --overlay           # ทั้งโฟลเดอร์
python crack_detector.py a.png b.png --out results/ --prob         # ระบุไฟล์ และบันทึกภาพความน่าจะเป็นด้วย
python crack_detector.py scans/ --out results/ --thr 0.3 --min-area 0 --tile 1024 --cpu
```

ไฟล์ที่ได้ในโฟลเดอร์ผลลัพธ์:
- `<ชื่อ>_mask.png`: mask ขาวดำ ขาว = รอยแตก
- `<ชื่อ>_overlay.jpg`: ภาพเดิมที่ระบายรอยแตกเป็นสีแดง (เมื่อใส่ `--overlay`)
- `<ชื่อ>_prob.png`: ภาพความน่าจะเป็น ×255 (เมื่อใส่ `--prob`)

ชื่อไฟล์ภาษาไทยใช้ได้

## ความแม่น

### ภาพสแกนทดสอบของเรา

ใช้ 681 ภาพ (2048×2048) ที่ไม่ได้ใช้เทรน วัดที่ threshold 0.16 และตัดบริเวณที่เล็กกว่า 150 pixel ทิ้ง

| วัดอะไร | รุ่นนี้ | รุ่นก่อน (1 คลาส) | 3 คลาส V3 |
|---|---|---|---|
| รอยแตกที่ label ไว้ที่หาเจอ | **638 จาก 896 (71.2%)** | 562 (62.7%) | 600 (67.0%) |
| ภาพที่ไม่มีรอยแตกแต่โมเดลแจ้งว่ามี | **167 จาก 441 (37.9%)** | 257 (58.3%) | 200 (45.4%) |
| รอยต่อที่ถูกทายเป็นรอยแตก | **14 จาก 358** | 174 | 22 |
| pixel ที่ทายเป็นรอยแตกและอยู่ใกล้รอยแตกจริง (ภายใน 5 pixel) | **70.6%** | – | 66.6% |

ตัวเลขแจ้งเตือนผิดสูงเกินจริง เพราะ label รอยแตกในภาพทดสอบไม่ครบ
ผู้ใช้เคยสุ่มตรวจภาพที่ถูกนับว่าแจ้งเตือนผิด 50 ภาพ พบว่า 18 ภาพมีรอยแตกจริง

### ชุดทดสอบสาธารณะ

| วัดอะไร | รุ่นนี้ | รุ่นก่อน |
|---|---|---|
| crack_merged test 1,695 ภาพ: F-score (คลาดได้ 2 pixel, threshold 0.16) | 0.861 | 0.876 |
| crack_merged test: IoU (ตรงทุก pixel, threshold 0.5) | 0.596 | 0.616 |
| crack_merged test: AP | 0.876 | 0.913 |
| F-score เฉลี่ยบนภาพเสีย 10 แบบ (มืด, สว่างเกิน, เงา, noise, เบลอ, JPEG ฯลฯ) | 0.851 | 0.869 |
| F-score ในกรณีที่แย่ที่สุด (ภาพเบลอจากการเคลื่อนไหว) | 0.837 | 0.855 |
| F-score บนภาพ line-scan ถนนสาธารณะ (CRKWH100 + CrackLS315, 80 ภาพ) | 0.844 | 0.882 |

รุ่นนี้ทำได้ดีกว่าชัดเจนบนภาพสแกนของเรา แต่ได้คะแนนต่ำกว่ารุ่นก่อนเล็กน้อยบนชุดสาธารณะ
ถ้าใช้กับภาพประเภทอื่นที่ไม่ใช่ภาพสแกนของเรา รุ่นก่อนอาจเหมาะกว่า

### ความเร็วและการตรวจแพ็กเกจ

วัดบน RTX PRO 4000 Blackwell (bf16):
- ภาพสแกน 2048×2048: ราว 0.18 วินาที/ภาพ (ค่าเริ่มต้น `tile=2048`, หน่วยความจำ GPU ราว 5.7 GB)
- ภาพ 448×448 ส่งเป็น batch: ราว 120 ภาพ/วินาที รวมเวลาอ่านไฟล์

ผลการตรวจเทียบกับโค้ดที่ใช้เทรน:
- รันทีละภาพ: ค่าความน่าจะเป็นตรงกันทุก pixel ทั้งภาพ 8-bit และ 16-bit
- รันแบบ batch: ต่างกันเล็กน้อยจากการคำนวณ bf16 (mask ต่างกัน 38 จาก 1.6 ล้าน pixel) และ F-score เท่าเดิม 0.8614

## ข้อควรรู้

- **ข้อมูลที่ใช้เทรน:**
  - crack_merged ชุด train+val (CRACK500, Rissbilder, Volker, DeepCrack, GAPS384, CFD และอื่นๆ) และภาพ line-scan ถนนสาธารณะ (CRKWH100 + CrackLS315)
  - NHA12D
  - ภาพสแกนของเราที่มี label ราว 18,600 ชิ้น 448×448 (รอยต่อและรอยปะที่ label ไว้ถูกสอนว่าไม่ใช่รอยแตก)
  - ภาพสแกนใหม่เดือน ต.ค. 2026 ที่สร้าง label อัตโนมัติ ราว 12,000 ชิ้น
- **แถบตรงแนวนอนในภาพสแกนใหม่:** ภาพสแกนเดือน ต.ค. 2026 บางภาพมีเส้นตรงยาวที่ลายผิวถนนเหลื่อมกัน (น่าจะเป็นรอยต่อของตัวภาพสแกน) โมเดลอาจทายเส้นนี้เป็นรอยแตก
- **ความกว้างของรอยแตกที่ทำนาย:** แต่ละแหล่งข้อมูลวาด label ไม่เหมือนกัน บางแหล่งวาดแค่เส้นกลางกว้าง 1 pixel บางแหล่งวาดเต็มความกว้างของรอยแตก ถ้าต้องวัดความกว้างให้แม่นยำ ควรปรับ `threshold` โดยเทียบกับภาพที่รู้ความกว้างจริง
- **รูปแบบไฟล์ weight:** `torch.load(..., weights_only=True)` ให้ dict ที่มี `state_dict`, `threshold`, `min_area`, `test_metrics` และข้อมูลการเทรน ดูได้จาก `det.info`
- **ที่มา:** weight มาจาก checkpoint สุดท้าย (`last.pt`) ของ run `deepcrack_convnext_small_final_aug_1class_own` (EMA weights) เทรนด้วย preset `convnext_small_final_aug_1class_own` ของโค้ดเทรน ซึ่งไม่ได้รวมอยู่ใน repository นี้
- **รุ่นก่อน:** แพ็กเกจ `crack_detector_1class_2026-11-17` ไม่ได้รวมอยู่ใน repository นี้
